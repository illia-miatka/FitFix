# FitFix — контекст для Claude Code

Сервіс, що виправляє тренування з битим GPS: бере **час і сенсори** з оригінального FIT і **геометрію** з еталонного треку (FIT/GPX/TCX), та генерує новий FIT, який коректно імпортується у Strava.

Мова спілкування — українська. **Артефакти — англійською:** повідомлення комітів, документація, коментарі в коді, назви файлів, стори. Користувач — Ілля (бігун, Київ).

## Звідки проєкт

Почалося з реального кейсу 19.11.2026:
- `Run_4k_Chabany.fit` — оригінал (експорт «Sauce for Strava»). GPS-дистанція «замерзла» на 3911 м приблизно на 1313 с, хоча пульс 150–159 тримався до кінця (2162 с). Позиції ще ~збігались з реальним маршрутом до ~1700 с, далі сміття/зависання.
- `FFF.fit` — правильний трек з онлайн-редактора (6537 м), але **зламаний час**: увесь маршрут стиснутий у перші 1311 с, далі одна точка-стрибок на 851 с до фінішу. Висота зсунута на −400.8 м (−218 замість 182.8). Немає event/activity-повідомлень.
- Обидва файли покласти в `tests/fixtures/private/` (gitignored — там приватні GPS-дані).

## Перевірений алгоритм (прототип у `prototype/`)

`prototype/fix.py` + `prototype/write.py` дали коректний результат (6.54 км, 36:02, ~5:30/км у Strava):
1. Трек → дедуплікація точок (<0.3 м), кумулятивна геодезична дистанція.
2. **Якорі:** кожну GPS-точку оригіналу проєктуємо на сегменти треку у монотонному вікні `[k-3, k+40]`; приймаємо, якщо відстань < 20 м, дистанція не спадає, швидкість між якорями ≤ 4.5 м/с (+3 м), і при dt ≥ 30 с швидкість ≥ 1.8 м/с (відсікає завислий GPS).
3. Кінцевий якір = (кінець активності, довжина треку). Лінійна інтерполяція між якорями.
4. Згладжування ковзним середнім (±15 с у надійній зоні, ±60 с у шумній) — монотонність зберігається.
5. Висота треку + зсув, що вирівнює старт з оригіналом.
6. Нульову потужність після збою GPS прибрано (пристрій рахував її з GPS-швидкості).
7. Запис FIT через `fit-tool`: file_id, event start/stop_all, record щосекунди, lap, session, activity.

**Стан портування в `src/FitFix.Core` (спайк 19.11.2026):**
- [x] Жорсткий cutoff `t > 1720` → `GpsStallDetector` (нерухомість ≤ 15 м протягом ≥ 90 с при ненульовому каденсі).
- [x] Поріг «1300 с» для нульової потужності → локальне правило: власна дистанція пристрою не зросла за останні 10 с.
- [x] Пороги швидкості за видом спорту → `AlignmentOptions.ForSport` (біг 7, вело 25, інше 15 м/с).
- [ ] Вибір найдовшого правдоподібного ланцюжка якорів (DP / LIS) — зараз жадібний набір. Сюди ж AD-21: згладжування обрізається межами пауз, але не межами Якорів.
- [x] Паузи (timer stop/start) оригіналу — `OriginalActivity.Pauses`, дистанція розподіляється по moving time (FR-5).
- [x] Кола (laps) оригіналу — `OriginalActivity.Laps` + `LapPartition`, записувач пише коло на кожен інтервал (FR-6).

Урок (SM-C1 у PRD): поріг якоря 35 м — погано, алгоритм чіпляється за сміття.

## Узгоджені рішення (для архітектури)

- Формат: повноцінний проєкт у репо — фронтенд + бекенд API + Docker. Strava-інтеграція — окремий епік **після** MVP (Strava API не віддає оригінальний FIT → відтворювати зі Streams; заливка через Uploads API).
- Еталонний трек: FIT, GPX, TCX. Малювання маршруту на карті — пізніше.
- Stateless: файли не зберігаються.
- Стек (вибрано 19.11.2026, перевірено спайком):
  - Backend: **.NET 10** (LTS; локально SDK 10.0.302), ASP.NET Core Minimal API (`src/FitFix.Api`, сторі 2.1), **`Garmin.FIT.Sdk` 21.222.0** — офіційний Garmin FIT SDK, читання й запис. GPX/TCX — `System.Xml.Linq`. Формат треку визначається за вмістом файлу.
  - Проєкти: `src/FitFix.Core` (чисте ядро, без вебу), `src/FitFix.Cli` (`fitfix repair ORIGINAL TRACK -o OUT`), `src/FitFix.Api` (Minimal API: `/health` і контракт відмов), `tests/FitFix.Core.Tests` і `tests/FitFix.Api.Tests` (xunit; API-тести ходять справжнім HTTP по Kestrel), `web/` (фронтенд, сторі 2.4).
  - Frontend: React 19, Vite 7, TypeScript, Tailwind 4 (`@tailwindcss/vite`), шрифти `@fontsource/unbounded` + `@fontsource/manrope`; тести — Vitest + Testing Library у jsdom. Далі в епіку 3: react-leaflet 5 + Leaflet 1.9 (темна підкладка CARTO), Recharts 3, lucide-react. Локально Node 26, npm 11.
  - Один Docker-образ: збірка фронту → статика роздається ASP.NET Core. `docker compose up`. Публічного хостингу в MVP немає.
  - API (чернетка): `POST /api/inspect` (метадані одного файлу), `POST /api/repair` (multipart: original, track → JSON-звіт + FIT у base64).
- Дизайн: темний графіт, один лаймовий акцент `#C8F135` для виправленого треку, пунктир `#7C8594` для оригіналу, `#F5B83D` для розрахованої зони. Не використовувати помаранчевий Strava-брендинг.

## Фронтенд (`web/`, сторі 2.4)

```bash
npm --prefix web install      # один раз
npm --prefix web run dev      # Vite на :5173, /api проксюється на Kestrel :5000
npm --prefix web run typecheck
npm --prefix web run build
npm --prefix web run test     # Vitest
```

- `src/theme.css` — **єдине** місце, де взагалі є колір, радіус чи крок сітки. Токени DESIGN.md живуть у `@theme` (Tailwind 4 бере тему з CSS, окремого конфіга немає), три типографічні ролі — `@utility type-display|type-body|type-metric`. `theme.test.ts` падає на будь-якому hex поза цим файлом.
- `src/i18n/uk.ts` — **єдине** місце з текстом для людини. `uk.test.ts` тримає ключі `codes` рівними `DiagnosticCodes.All`: він парсить сам `DiagnosticCodes.cs`, а не копію списку, тож новий код у ядрі одразу валить тест, поки йому не напишуть український текст (AD-18).
- `prefers-reduced-motion` вимикає анімації глобально в `theme.css`, не покомпонентно.
